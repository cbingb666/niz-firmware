本次分析针对 `66EC(RGB)BLe_V1.5.1_20230520.bin`。已恢复完整的更新文件所承载的程序字节，导出其可识别函数，并用配套 HWI DLL 核对通信。以下地址和常量来自解密镜像；功能名称由静态分析补充，未识别的函数保留 `FUN_地址` 名称。

后续已完成 [C + 汇编完整重建工程](../firmware/README.md)。整个 53,584 字节 APROM 镜像和原厂封装逐字节重建通过，源码 ZIP 在不含原始输入的目录内独立构建通过。大多数功能使用可编辑汇编，扫描队列处理入口另提供经过 ARM 对照的 C 版本；自动 C 导出的可编译性限制仍然适用。

## 加密封装

每行格式是 `:`、一个十六进制长度字节、DES 密文。长度表示完整明文 Intel HEX 记录的字节数，包含记录头和校验和。明文补零到八字节倍数后，逐块使用 DES ECB 加密；行间没有链式状态。

固件的 `des_ecb_decrypt` 位于 `0x7ECC`。调用者在 `0x918C` 使用 ROM `0x9364` 的常量 `0x00000076`。DES 实现清空八字节密钥缓存，只复制调用者提供的第一个字节，因此实际密钥为 `76 00 00 00 00 00 00 00`。DES 忽略每字节的奇偶校验位，首字节换成 `77` 会得到相同结果；最终解包器使用 ROM 对应的 `76`。

首条解密记录为 `:020000040000FA`，随后是地址零处的向量表，最后是标准 EOF `:00000001FF`。全部记录校验与重新加密验证通过，解密不是通过挑选少数看起来像代码的字节确定的。

## 按键扫描算法

采样队列的每条记录有七个字节：行号加六个列样本。采样入口根据空闲 ADC 电平与当前读数的差值生成八位样本；它们不是未经处理的十位 ADC 值。

过滤函数先减去每键基线。它对同一行其他列的变化量计算补偿，RGB 关闭时系数为 5%，开启时为 18%；当前列变化量超过 10 时才加入补偿，并保留原程序的八位回绕行为。达到按下阈值或低于释放阈值时，需要累积三次相应状态才生成事件。释放阈值为按下阈值减 3，滞回区保留消抖计数。

事件高位为按下标志，低七位为物理键编号。人工整理的 [key_scan.c](readable/key_scan.c) 提供单条记录接口。后续的 [ARM C 扫描模块](../firmware/src/scan.c) 已恢复完整队列处理入口，并实际链接进 `c_scan` 镜像；定时中断和校准加载在完整汇编工程中保留原指令。

## 自动分析的修正与剩余限制

ARMCC 使用 `ADD PC` 和字节偏移表实现分支。手工恢复了 `0x2766`、`0x30AE` 和 `0xB4BE` 三张表，主循环的五个状态能够完整导出。`0x59F6` 和 `0x5A0E` 使用 BL 指令作函数内长跳转，已按实际栈帧关系修正。软件 I2C 的小汇编辅助函数按实际寄存器保留关系内联，修正了 EEPROM 字节读取的返回值推断。

自动 C 仍有推断类型、部分结构未恢复和编译器辅助函数的调用约定细节；成功生成伪代码不等于每行语义已经证明正确。完整工程通过汇编重建所有原程序字节，允许逐模块替换为经验证的 C。Ghidra 在 `0xBD58` 之后误把部分常量、表格和描述符识别为指令；构建源码已按数据处理，整镜像一致性验证通过。无线部分恢复到 UART 报告和控制协议，外部模块内的射频及 BLE 协议栈不属于本镜像。

新构建验证包括 ARM C 的 16,599 条记录及每次完整全局 RAM 对照，以及更新函数的全部记录暂存、完成标记和四种拒绝路径。EEPROM 和最终配置 Flash 操作用模拟回调实现，实际 USB 更新及 LDROM 写回尚未验证，见 [交付验证报告](../firmware/dist/verification.json)。
